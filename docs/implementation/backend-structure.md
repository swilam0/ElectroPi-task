## Middleware Order

The order of middleware/guards/pipes in NestJS is critical for security and correctness:

```
Request
  │
  ▼
[1] LoggerMiddleware          — Logs method, URL, duration, requestId (correlation)
  │
  ▼
[2] JwtAuthGuard              — Verifies Bearer token, sets req.user
  │
  ▼
[3] RolesGuard                — If @Roles() present, checks user.role
  │
  ▼
[4] ValidationPipe (global)   — Validates body/query/params with DTOs
  │
  ▼
[5] Controller Handler        — Delegates to service
  │
  ▼
[6] Service                   — Business logic, repository calls
  │
  ▼
[7] Repository                — Prisma queries
  │
  ▼
[8] Return                    — Controller returns value → serialized as JSON
```

## Naming Conventions

| Artifact | Convention | Example |
|----------|------------|---------|
| Files | `kebab-case` | `jwt-auth.guard.ts` |
| Classes | PascalCase | `JwtAuthGuard` |
| Functions/Methods | camelCase | `findByProject()` |
| DTOs | PascalCase + suffix | `CreateTaskDto` |
| Interfaces | PascalCase + `I` prefix | `ITaskRepository` |
| Enums | PascalCase | `TaskStatus`, `Role` |
| Enum values | UPPER_SNAKE_CASE | `IN_PROGRESS`, `ADMIN` |
| Routes | kebab-case | `/api/projects/:pid/members` |
| Prisma models | PascalCase, singular | `ProjectMember` |

## Conventions

- **Repository pattern:** Every module has a repository class that depends on `PrismaService`. The repository implements an interface defined in `common/interfaces/`.
- **DTOs define the contract:** Every request body has a corresponding DTO with `class-validator` decorators. DTOs are defined at the controller boundary.
- **No raw Prisma in services:** Services depend on repository interfaces, not on `PrismaService` directly.
- **Error handling:** Services throw typed exceptions (custom `DomainException` subclasses). The global exception filter catches them and formats JSend responses.
- **Configuration:** All env vars are validated at startup in `env.config.ts` using `@nestjs/config` with a Joi schema.
- **Module isolation:** Modules only import what they need. `PrismaModule` and `RedisModule` are global. `AuthModule` exports `JwtModule` and `JwtStrategy` for use by guards.

## API Documentation

- **Tool:** `@nestjs/swagger` (OpenAPI 3.0 specification)
- **Setup:** `SwaggerModule.setup('api/docs', app, document)` in `main.ts`
- **Dev URL:** `http://localhost:3001/api/docs`
- **Decorators:** `@ApiProperty()` on DTOs for request/response schemas, `@ApiTags()` and `@ApiOperation()` on controllers, `@ApiBearerAuth()` on protected endpoints
- **Production:** Swagger UI is disabled when `NODE_ENV=production` via conditional guard in `main.ts`
